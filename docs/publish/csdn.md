# 开源了一个可视化桌面自动化工具：像画流程图一样做 RPA

做桌面自动化的同学大概都有这种经历：脚本写了两百行，某天要改"登录后多等两秒"这一个细节，翻代码翻了十分钟，改完还不敢确定有没有改错地方。

最近把自己写的一个开源项目整理上架了，思路很简单：**把每个动作变成一个节点，把执行顺序变成连线**。拖拽连线，看起来就是流程本身。

项目名叫 Visual Automation Designer，地址在文末。

## 它是一个什么东西

技术栈是 Tauri 2 + React 18 + ReactFlow 11，后端执行引擎用 Rust 写。也就是说：界面是网页技术，但真正点鼠标、截屏、做图像匹配的是原生 Rust 代码，不是浏览器沙箱里的模拟。

跟市面上的图形化 RPA 比，它有两点不太一样：

第一，它是**单机、离线、开源**的。流程存在本地 JSON 里，不经过任何服务器。

第二，它的核心是**图像识别驱动**——不是靠元素选择器，而是靠"屏幕上有没有这张图"来判断。这听起来原始，但对那些没有 API、没有可访问性树的老软件、游戏、远程桌面场景，反而是唯一能用的办法。

## 十个节点，覆盖大部分场景

动作类：

- 点击（按坐标，或按图片定位）
- 等待图片（图出现就继续，超时则停下）
- 等待时间
- 输入文本（可调逐字输入间隔）
- 截图断言（和参考图比对，有阈值和严格模式）
- 文本提取（从指定区域识别文字）

控制类：

- 循环、无限循环
- 条件判断（图在不在，走两条分支）
- 文本检查（识别到的文字里有没有关键词）

把「条件判断」和「截图断言」组合起来，就能写出"如果弹窗出现了就点掉，没出现就继续"这种逻辑，不用写一行代码。

## 五分钟跑通第一条流程

1. 去 Releases 下载对应系统的安装包，Windows 是 exe，mac 是 dmg，Linux 是 AppImage。
2. 打开后先在「图片库」上传一张参考图，比如某个按钮的截图。
3. 新建流程时可以直接选模板「入门：等图 → 点击 → 等待」，三个节点和两条连线会自动摆好；也可以从左侧手动拖节点。
4. 把节点里选的图片换成你刚上传的那张，超时和等待时长按需改。
5. 按 F5 执行，底部日志会一步步打印执行过程。

中间哪一步失败，日志会直接告诉你：是等图超时，还是断言没通过。这比自己 print 调试快得多。

按 F10 可以单步执行，当前正在跑的节点会高亮，配合日志定位问题很直观。

## 一些实践里踩出来的经验

参考图别截太大。带上一大片背景，界面稍微变一点就匹配不上；只截目标元素本身，成功率会高很多。

缩放比例要一致。显示器 DPI 换了、远程桌面连进来，坐标和图像尺寸都可能变。项目里做了 DPI 自适应纠偏，但最稳的还是重新截图。

流程文件记得备份。Windows 下在 `%APPDATA%\com.visualautomation.designer\flows.json`，这一个文件就是全部流程。

## 为什么把它开源

这类工具的开发成本主要在细节：截图匹配的容错、执行引擎的取消与单步、撤销重做的状态一致性。这些坑我自己踩了一遍，与其烂在硬盘里，不如开源出来让别人少踩一次。
