# 把重复的鼠标键盘操作，画成一张流程图

每天早上打开电脑，重复同一套动作：开软件、登录、点签到、关弹窗。动作本身不难，难的是它每天都要占用我的注意力。

这些操作我写过脚本，也用过按键精灵那类工具。问题都出在同一个地方：**流程藏在代码里，看不见**。三个月后回来看，得从第一行重新读一遍才能想起来当时为什么在这里等了两秒。

所以我做了个小工具，把流程画出来。

## 画布就是流程本身

工具打开是一张空白画布，左边一排"积木"：

点一下这个位置、等这张图出现、输入这段文字、这里如果出现了弹窗就走这条路……

把积木拖到画布上，用鼠标连起来，就是执行顺序。改流程不用改代码，把节点挪个位置、把等待时间从 2 秒改成 5 秒，拖一下就完事。

它叫 Visual Automation Designer，桌面软件，Windows、macOS、Linux 都有安装包，开源的。

## 为什么用"看图"而不是"找元素"

大多数自动化工具靠元素的 ID 或文本定位。这在现代网页上很准，但遇到老软件、游戏客户端、远程桌面、一些没有可访问性接口的国产软件，就完全失灵——那些界面上根本没有可供程序查询的元素。

这个工具走的是另一条路：截图比对。

你把要点的按钮截一张图存进图片库，流程里写"等待这张图出现"，它就一帧帧比对屏幕，直到匹配上（或超时）。点击也一样，按图定位，窗口挪了位置也不影响。

听起来笨，但在我试过的场景里，这是唯一"什么软件都能用"的办法。判断逻辑也能靠它做：条件节点判断"某张图在不在"，在就走 A 路，不在走 B 路。

## 跑起来是什么样

装上之后，做一个"自动签到"流程大概是这样：

先截一张签到按钮的图，传到图片库。然后拖三个节点：等待图片（选这张图，超时设 15 秒）、点击（同样选这张图）、等待时间（填 1.2 秒，给界面反应时间）。连起来，保存，按 F5。

执行时底部会滚动日志，每一步开始、结束、耗时都写出来。哪一步卡住了，日志会直接说是等图超时还是断言没过——比脚本里到处 print 舒服得多。

调试的时候按 F10 可以单步跑，当前执行到哪个节点，画布上就高亮哪个。这个设计我自己用得最多，改流程的时候一眼就能看出逻辑对不对。

## 踩过的坑，写进文档里了

参考图不要截太大。连着背景一起截，界面稍微变一点就匹配失败。

显示器的缩放比例、远程桌面的分辨率都会影响匹配。工具里做了自适应纠偏，但最稳妥的做法是换环境后重新截一次图。

流程数据是本地一个 JSON 文件，Windows 在 `%APPDATA%\com.visualautomation.designer\flows.json`，备份它就行。

这些细节都写在仓库的使用教程里，从安装到第一个流程大概十分钟。

## 一点想法

做这类小工具最大的收获不是工具本身，而是发现"可视化"这件事的边界比想象中清晰：能拖拽表达的，是**结构**；真正要落在代码里的，是**容错**。

节点和连线可以画出来，但"图匹配到 92% 算不算成功"、"超时了要不要重试三次"、"点击后界面没变化怎么判定"——这些判断没法拖拽，只能一条条想清楚。

所以工具做的不是"让人不写代码"，而是把人从重复劳动里挪出来，去做那些真正需要判断的部分。
